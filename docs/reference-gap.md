# 누나가 보낸 화면 자료 기준 구현 경계

원본: `통합 문서1.xlsx`의 `Sheet1` 설명 12개와 삽입된 캡처 9장. 원본 파일과 캡처는 이 저장소에 포함하지 않는다. 캡처는 화면 조각이며 해상도와 브라우저 배율이 달라 절대 픽셀 좌표를 운영 코드에 사용하지 않는다.

## AO에 대해 캡처만으로 알 수 없는 것

- `.sapaox`를 실제 Excel/SAP AO에서 여는 호출 방식과 다운로드 후 브라우저/Windows 보안 동작.
- 프롬프트 확인 후 조회가 끝났음을 감지하는 방법과 시간 초과·재로그인 처리.
- 조회 결과의 실제 시트 구조, 열 위치, 병합 셀, 수식, 연결 정보와 `결과`행 의미.
- 실제 SAP 연결의 자동화 허용 범위와 저장 시 연결 유지 여부.

실제 운영 모드를 만들려면 Windows 업무 PC에서 화면 관찰과 실제 AO 조회 결과 파일의 구조 검사가 필요하다. `capture-real.cmd`와 `inspect-ao.cmd`는 그 증거를 모으는 단계이며, 실제 AO 프롬프트 자동 입력·HiCloud 저장·회사 메일 전송은 아직 구현하지 않았다. 현재 `runner.py`의 전체 흐름과 `excel_adapter.py`의 가공은 시뮬레이터 전용이다. 원본 자료에는 메일 수신자·제목·본문·발송 화면이 없다.
